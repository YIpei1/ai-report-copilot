# 报表模块接口文档

## Apifox 导入文件

请直接导入以下 OpenAPI 3.0 文件：

```text
doc/报表模块.openapi.json
```

该文件包含：

- 检测模板接口。
- 报表组件接口。
- 创建检测所需的设备、工具箱和仪器接口。
- 报告列表、详情、新增和更新接口。
- 查询参数、路径参数和请求体。
- 公共响应、业务数据和快照数据模型。
- Bearer Token（令牌认证）配置。
- 接口中文名称、分组和字段说明。

## 导入步骤

1. 打开 Apifox 项目。
2. 进入“项目设置”。
3. 选择“导入数据（手动导入）”。
4. 选择 OpenAPI/Swagger 文件导入。
5. 上传 `doc/报表模块.openapi.json`。
6. 在导入预览中确认接口、数据模型和环境。
7. 已经导入过旧版本时，建议使用“智能合并”。

Apifox 官方支持导入 OpenAPI 3 的 JSON 或 YAML 文件：

[Apifox 导入 OpenAPI（Swagger）数据](https://apifox.com/help/api-manage/import-api/swagger)

## 接口分组

导入后生成三个接口目录：

```text
检测模板
创建检测依赖
检测报告
```

## 当前基础地址

OpenAPI 文件中的开发环境地址为：

```text
/api
```

如果 Apifox 需要直接请求本地 Vite 服务，可以在 Apifox 环境中配置完整前置 URL，例如：

```text
http://localhost:5173/api
```

端口以本地 Vite 实际启动地址为准。

## 维护约定

接口发生变化时，优先更新：

```text
doc/报表模块.openapi.json
```

然后重新导入 Apifox。OpenAPI 文件是接口结构的机器可读来源，本 Markdown 只保留导入和维护说明。

当前 OpenAPI 文件反映的是前端 MSW Mock 接口。后续接入真实后端时，需要同步确认：

- 接口地址。
- HTTP 方法。
- 请求参数。
- 响应结构。
- 错误码。
- 报告快照保存策略。
